# Security Policy

**ZeroControlStudios**
Independent Development Studio
France

## 1. General Principle

Security is a shared responsibility across ZeroControlStudios projects and infrastructure.

Access to systems and information must be limited to what is necessary for legitimate development or operational purposes.

## 2. Account Security

Individual accounts must be used whenever technically possible.

Users must not:

* share passwords;
* share authentication tokens;
* share private keys;
* reuse credentials belonging to another person;
* bypass security controls;
* or intentionally weaken security mechanisms.

Multi-factor authentication should be enabled wherever available.

## 3. Secrets

Passwords, API keys, private keys, authentication tokens, database credentials, and similar secrets must not be stored in public repositories.

Secrets should be stored using appropriate secret-management mechanisms.

## 4. Security Incidents

Suspected security incidents should be reported as soon as reasonably possible through the appropriate ZeroControlStudios security channel.

Examples include:

* leaked credentials;
* unauthorized access;
* suspicious repository activity;
* accidental publication of private information;
* compromised accounts;
* or suspected data exposure.

## 5. Vulnerability Disclosure

Security vulnerabilities affecting ZeroControlStudios systems should be reported privately rather than publicly disclosed before the issue has been assessed.

## 6. Logging

Where appropriate and lawful, ZeroControlStudios may maintain technical logs relating to:

* authentication;
* access;
* repository activity;
* infrastructure activity;
* security events;
* and administrative actions.

Such logs may be used for security, auditing, incident response, and operational purposes.

## 7. Access Revocation

Access may be revoked when:

* a person's role changes;
* access is no longer required;
* an account is compromised;
* a security incident occurs;
* or the person's collaboration with ZeroControlStudios ends.
